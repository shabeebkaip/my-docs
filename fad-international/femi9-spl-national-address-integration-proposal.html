Section 1
The Problem — Why Orders Miss the Mark
We reviewed femi9.com's live checkout directly. It runs on Magento 2, and — like the overwhelming majority of Magento stores in the region — its address capture leans on Google Maps for pin-dropping and location lookup. Google Maps geocoding is built for global consistency, not for Saudi Arabia's addressing reality: many residential compounds, new districts, and informally named streets simply aren't mapped with building-level precision. The customer drops a pin that looks right on screen, and the courier still ends up at the wrong villa or the neighbor's gate.
What This Costs femi9

Every misdelivered order means a failed first attempt, a redelivery trip, a delayed customer, and — in fashion e-commerce, where first impressions drive repeat purchase — a real risk of return or lost trust. This is a fixable, structural problem, not a one-off logistics hiccup.

2
Section 2
The Solution — SPL National Address
SPL (Saudi Post) operates the Kingdom's official National Address system — a government-mandated addressing standard where every location has been surveyed to roughly 1 square meter of accuracy. Each address resolves to a structured format (building number, street, district, city, postcode, additional number) and to a memorable Short Address: 4 letters followed by 4 digits, e.g. RRRD3005. Registration is free for individuals and businesses, and short addresses can already be looked up through SPL Online, Absher, Tawakkalna, Sehhaty, and Maha — meaning most femi9 customers in Saudi Arabia either already have one or can get one in minutes.

Not an either/or

We are not proposing to rip out femi9's existing map-based address flow. SPL National Address is layered in as the primary, verified path, with the current pin-drop kept as a fallback for the small number of customers without a registered address yet — see Section 5 for the exact flow.

Section 5
How It Plugs Into femi9's Magento 2 Checkout
Confirmed by direct technical review

femi9.com is built on Magento 2 (confirmed via the checkout page's core Magento markup and form_key security token). The checkout already carries Tamara for buy-now-pay-later and an Aheadworks popup module, alongside a dormant "National Address Code" field (Section 3) and heavy reliance on Google for maps/address lookup. This tells us exactly where the integration needs to sit — inside the existing shipping-address step, reusing the field that's already there, without touching payment or promo logic.

Checkout Flow
1
Customer enters their SPL Short Address
  • The dormant National Address Code field (Section 3) becomes live: the customer types their 8-character Short Address (e.g. RRRD3005), with the map pin kept as a visible fallback for anyone who doesn't have one yet.
2
Magento calls SPL to verify and expand it
  • FullNAByShortAddress resolves the Short Address into the full verified address — building number, street, district, city, postcode, additional number — plus exact coordinates.
3
Pin-drop customers get reverse-validated
  • If a customer still drops a pin, FullNationalAddressByGeocode checks that latitude/longitude against the National Address database and offers the verified address as a one-click confirmation before checkout completes.
4
Verified address travels with the order
  • The verified address and precise geocode are saved to the Magento order and passed to the courier — no more guesswork on the last mile. GeoCodeByShortAddress and NationalAddressByShortAddress support lighter lookups for saved address books and repeat customers.
The 4 SPL APIs This Integration Uses
# API & Purpose
01 FullNationalAddressByGeocode Input: latitude/longitude. Output: full verified address + Short Address. Used to validate/enrich a customer's map pin.
02 FullNAByShortAddress Input: Short Address (e.g. RRRD3005). Output: full address + coordinates. The primary lookup used at checkout.
03 NationalAddressByShortAddress Input: Short Address. Output: lightweight address payload (no coordinates) — used for address-book display and confirmation screens.
04 GeoCodeByShortAddress Input: Short Address. Output: coordinates only — used to hand off precise pickup/drop coordinates to the courier's routing system.
Built-in safety net

SPL's own API contract already defines clean success/failure responses with error codes for every edge case (invalid address, quota limits, service downtime). We fall back to femi9's current manual address entry whenever SPL can't resolve a lookup — the new flow can only make checkout more accurate, never block an order.
