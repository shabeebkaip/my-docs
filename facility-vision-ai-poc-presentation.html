02 / POC scope

5–10 cameras, split across the two CCTV use cases.

The UPS and fire pump agents run on a separate track — they depend on what's actually on those panels, which we can only confirm on site.

3–5 cameras · Access control

Positioned at the entry point(s) of the restricted / controlled area(s) named on the call, to validate the entry-detection and authorization logic end to end.

2–5 cameras · Dispatch line

Positioned to cover the main line and the hand-off point where colour-tagged equipment is placed, to validate colour/label detection and the mis-route alert.

Site assessment · UPS & fire pump

Not camera-count scope — this is a panel and controller assessment. Outcome decides whether the agent reads a screen (Tier A) or talks to the panel directly (Tier B, recommended). See section 05–06.

POC success criteria: the agent correctly flags an unauthorized entry and a correctly-tagged-but-misplaced shipment in live testing, with a notification landing on WhatsApp or the dashboard within seconds — plus one full automated UPS (or fire pump) test cycle producing a report, on whichever system the site assessment clears first.

03 / Agent 1 — Restricted-area access control

Every entry gets checked. Only the exceptions interrupt anyone.

Step 1
Camera at entry point
  • RTSP feed, existing or new camera
  • Continuous person detection
Step 2
Authorization check
  • Match against allow-list or
  • Cross-check existing access-control log
Step 3
Rules engine
  • Authorized → logged, silent
  • Unauthorized → alert fires
Step 4
Notification + audit log
  • WhatsApp / dashboard alert
  • Timestamped snapshot stored
Every entry is logged either way — the audit trail is the byproduct, the real-time alert is the point.
Three ways to define "authorized" — POC uses the fastest one

Tier 1 · Time-window rule

Simplest POC version: any entry outside an approved schedule (e.g. after hours) is treated as unauthorized. No integration needed — ships fastest.

Tier 2 · Access-log cross-check

If a badge/turnstile system already logs who entered, the agent cross-references camera detection against that log for a true authorized/unauthorized read.

Tier 3 · Face enrolment

Enrolled-personnel face matching for sites without an access-control system to cross-reference. Highest accuracy, needs a one-time enrolment step and written consent per local data-privacy practice.

One question for the technical call: does the site already run a badge or turnstile access-control system? If yes, Tier 2 is the POC default — it's more accurate than Tier 1 and needs no enrolment step like Tier 3.

04 / Agent 2 — Wrong-site equipment detection

If a red-tagged shipment lands on the main line, someone gets told before it moves further.

Step 1
Camera on the line
  • Watches the hand-off / main-line point
Step 2
Colour / label detection
  • Classifies tag colour on equipment
  • Reads label text if present (OCR)
Step 3
Routing rule check
  • Expected destination per colour/tag
  • Flags mismatch with the line it's on
Step 4
Instant alert
  • Dispatch supervisor notified
  • Snapshot attached for verification
Same detection engine as Agent 1 — a different rule set, not a different system.

Needs confirming before build: the full colour-to-site map (red / green / yellow and any others), what "the main line" physically is, and whether tags are colour-only or carry printed text/barcodes too — printed text or a barcode makes this meaningfully more reliable than colour detection alone, since lighting can distort colour but not a barcode.

05 / Agent 3 — UPS automated monthly test

Configure it once. It runs itself every month after that.

Two build tiers, because the right approach depends entirely on what the UPS panel can actually expose — this is the one thing that can't be answered without seeing the panel.

Tier A — Camera-based (fast POC)
  • Camera reads the panel display via OCR at the scheduled time
  • Technician still manually trips the breaker as today
  • Agent logs pass/fail, generates the report, flags anomalies it can read off-screen
  • Ships without any electrical integration — good for proving the reporting/alerting loop fast
Tier B — Direct panel integration (recommended)
  • UPS talks to the agent over Modbus/SNMP/BMS, if the panel supports it
  • Agent can trigger the transfer test itself — no technician needed at the breaker
  • Reads real battery telemetry (voltage, runtime, health), not just a screen reading
  • The reliable, production-grade path — needs the panel spec sheet to confirm feasibility
What the scheduled run does, either tier

Configurable schedule

Set once — e.g. 26th of every month, 5:00 PM. Change anytime from the dashboard.

Automated test run

Fires the transfer test (Tier B) or the observation window (Tier A) exactly on schedule.

Auto-generated report

Pass/fail, readings captured, timestamped — ready for compliance filing, no manual write-up.

Maintenance alert

Battery degradation or any out-of-range reading pushes an immediate alert, separate from the routine report.

06 / Agent 3 (continued) — Fire pump automated test

Same engine, same schedule logic, a different panel.

Not a separate build — this reuses the exact scheduler, reporting, and alerting logic from the UPS agent above. The only new work is the panel-specific reading (pressure, flow, jockey-pump cycling) once the controller type is confirmed on site.

Why this is low-risk to add: once the UPS agent's scheduler, report generator, and alert pipeline exist, pointing the same pipeline at a second controller is configuration, not a new system. The fire pump test can typically launch in the same POC window as the UPS test, once the site visit confirms the controller type.

07 / How it all fits together

One platform, three agents running on it.

Input
Cameras (RTSP) + electrical panel data (OCR or Modbus/SNMP)

Existing CCTV feeds where available; new cameras only where the POC needs new coverage. UPS/fire pump input tier depends on the site assessment.

Edge / Inference
Local detection models — person, colour/label, panel OCR

Runs close to the cameras to keep alert latency low and avoid pushing raw video off-site unnecessarily.

Rules Engine
Per-agent logic: authorization checks, routing rules, test scheduler

This is where "who's authorized," "what colour goes where," and "test on the 26th at 5 PM" live — configurable without touching the detection models.

Notification
WhatsApp, email, and a live dashboard

Unauthorized entry, mis-routed shipment, or a failed test all land the same way — instantly, on the channel your team already checks.

Audit & Reporting
Every event logged with a timestamped snapshot; monthly reports auto-compiled

Doubles as your compliance record for UPS/fire pump testing and as an incident log for access events.

08 / POC plan

Four weeks, from site visit to a live pilot.

  • Week 1
    Site visit & assessment

    Confirm camera network access, walk the restricted area and dispatch line, and inspect the UPS/fire pump panels to decide Tier A vs Tier B. This is also where we confirm the colour-map and "main line" questions from section 04.

  • Week 2
    Build — access control & routing agents

    Configure the 5–10 POC cameras, deploy person and colour/label detection, wire up the authorization and routing rules confirmed in Week 1.

  • Week 3
    Build — UPS & fire pump scheduler

    Configure the test schedule, reporting template, and alert thresholds against whichever tier the Week 1 assessment cleared.

  • Week 4
    Live pilot & review

    Run all three agents live for a full cycle, tune false-positive/negative rates with your team, and walk through the results together before scoping the full rollout.
