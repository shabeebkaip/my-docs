Section 4
Red Flags
🚨 Red Flag 1 — Topology Claim Contradicts Official Product Documentation

The reseller's cover letter claims PRTG provides "Dynamic network maps" and "Infrastructure topology views." The official Paessler fact sheet — from Paessler themselves — explicitly states: "PRTG does not include network management such as configuration management, layer 2 or layer 3 topologies, auto-mapping." This is a direct contradiction. The BRD (FR-31/32) requires automatic L2/L3 topology discovery as a Should Have. If the reseller cannot demonstrate this feature in a POC, it is a scoring gap. Do not accept the proposal claim without a live demo.

🚨 Red Flag 2 — No Commercial Proposal Submitted

The BRD (Section 12) requires a commercial proposal including 3-year TCO, license model, and support SLA. None of this was submitted. PRTG licensing is sensor-based — for 1,000 nodes the correct SKU is PRTG XL1 (~USD 15–20K one-time + 25% annual) or PRTG Enterprise Monitor (subscription). Without a formal quote, commercial evaluation cannot proceed.

⚠ Red Flag 3 — Outdated Supporting Documents

The Paessler fact sheet submitted is dated March 2015 — over 10 years old. The product brochure is from November 2021. PRTG has evolved significantly since these documents. The current version is PRTG 24.x. Vendor should provide current 2025/2026 product datasheets and licensing information.

⚠ Red Flag 4 — Windows Server Only Core Deployment

All official documents confirm PRTG core server runs on Windows Server only. The BRD specifies a pre-provisioned VM — if that VM is Linux-based, PRTG cannot be installed. Confirm VM OS with the infrastructure team before proceeding. Remote probes can run on Linux but the core server cannot.

Section 5
Clarification Questions — To Send to Vendor

The following questions must be answered in writing before PRTG can be shortlisted for POC. Send to the reseller and require a formal written response within 5 business days.

  • 1
    Topology Mapping (FR-31/32): Your proposal references "Dynamic network maps" and "Infrastructure topology views." The official Paessler fact sheet states PRTG does NOT include L2/L3 topology auto-mapping. Please clarify: Does PRTG automatically discover and render Layer 2 and Layer 3 network topology from CDP/LLDP data? If not, what topology visualisation is actually provided? Provide screenshots from a live environment.
  • 2
    License Tier & Sensor Count (NFR-06): For 1,000 monitored nodes with approximately 5–8 sensors per device, the estimated sensor count is 5,000–8,000 sensors. Which PRTG license tier are you proposing (PRTG 5000, XL1, or Enterprise Monitor)? Please provide a formal commercial quotation including Year 1 license cost, annual maintenance for Years 2 and 3, and total 3-year TCO.
  • 3
    NCA ECC 2018 Compliance (BRD Section 10): Our environment is subject to Saudi Arabia's NCA Essential Cybersecurity Controls 2018. Please confirm your compliance posture against NCA ECC controls relevant to monitoring tools — specifically data residency (all data on-premises), encrypted credential storage, audit logging, and access control. Provide any applicable compliance documentation.
  • 4
    Deployment OS (NFR environment): PRTG core server is documented as Windows Server only. Our pre-provisioned VM environment — please confirm whether PRTG core server can be deployed on a Windows Server VM and confirm supported Windows Server versions (2019/2022). Provide minimum vCPU, RAM, and storage specifications for 1,000 nodes.
  • 5
    Active Directory / LDAP Authentication (FR-48): Does PRTG support Active Directory or LDAP-based user authentication? If yes, which PRTG version introduced this and is it available in the license tier you are proposing?
  • 6
    KSA Regional Support (NFR): Who is the authorised PRTG reseller / support partner in the Kingdom of Saudi Arabia? What are the local support SLA tiers available? Is Arabic-language support available? Provide references from at least one KSA or GCC healthcare or government organisation currently running PRTG.
  • 7
    CDP/LLDP Discovery (FR-03): Does PRTG natively parse CDP and LLDP data from Cisco switches to discover and map neighbour relationships? If yes, please confirm the specific sensor or method used, and whether this populates the device inventory automatically or requires manual configuration.

Preliminary Assessment & Next Step
✅ PRTG Strengths (vs. BRD)

Strong core monitoring — SNMP v1/v2c/v3, NetFlow/sFlow/IPFIX, WMI, ICMP all confirmed. Dashboard builder, scheduled reports, REST API, and multi-site remote probe architecture are solid. 150,000+ global installations and 27-year track record provide confidence. Healthcare sector listed as a target vertical. Fast time-to-value post-installation.

⚠ PRTG Weaknesses (vs. BRD)

Windows Server only for core. No native L2/L3 topology auto-mapping (reseller claim is inaccurate). No native ServiceNow connector (webhook only). NCA ECC compliance not addressed. License tier not specified. KSA local support not formally confirmed. Outdated documents submitted.

📋 Recommended Next Action

Step 1: Send the 7 clarification questions above to the reseller. Set a 5 business day deadline for written responses.

Step 2: On receipt of answers, re-evaluate the topology mapping claim. If PRTG cannot demonstrate L2/L3 auto-discovery in a live demo, downgrade this gap in the BRD scoring.

Step 3: Request a commercial quotation — PRTG XL1 or Enterprise Monitor for 1,000 nodes, 3-year TCO.

Step 4: Confirm VM OS compatibility before any POC scheduling.

Do NOT shortlist for POC until written answers to Q1 (topology), Q2 (pricing), and Q3 (NCA ECC) are received.
