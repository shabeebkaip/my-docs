Section 6
Warranty & Post-Delivery Support
6.1  6-Month Warranty
The project includes a 6-month warranty period from the date of final project sign-off. During the warranty period, the following are covered:
  • Bug fixes related to the delivered functionality.
  • Resolution of issues related to the existing implementation.
  • Fixing functional issues within the agreed project scope.
  • Technical support related to the delivered website and CMS.
The warranty does not include new features, major changes, enhancements, changes to third-party services, or requirements outside the originally agreed scope. Any such requirements will be assessed and estimated separately.
6.2  Support After Warranty / AMC
After the 6-month warranty period, ongoing maintenance and technical support can be provided through an Annual Maintenance Contract (AMC).
  • AMC cost: typically 15–20% of the total project cost, depending on the required support scope and agreed SLA.
  • Support scope: bug fixes, technical maintenance, troubleshooting, application monitoring, and minor maintenance activities related to the existing system.
  • New features / enhancements: any new functionality or major changes will be estimated and charged separately.
  • Response time: support requests are reviewed and responded to based on their priority and the agreed SLA under the AMC.
6.3  Hosting
  • Hosting provider / type: Hostinger VPS.
  • Ongoing hosting cost: annual Hostinger VPS renewal is approximately SAR 800–1,000, depending on the selected plan and applicable renewal pricing.
  • During warranty: application-related hosting and technical support are handled by our team, where applicable.
  • After warranty: hosting renewal costs and ongoing hosting responsibility are handled by the client unless otherwise covered under an AMC agreement.

Section 8
Website & Database Backup
An automated weekly database backup process has been configured. The backup flow is:
MongoDB Atlas→ MongoDB Dump→ ZIP Backup→ Hostinger VPS + Client Email
  • The Vitality MongoDB database is automatically backed up every Thursday at 7:30 AM Saudi Arabia time.
  • The database is exported using MongoDB backup tools and compressed into a ZIP file.
  • A copy of the ZIP backup is stored on the Hostinger VPS, and a copy is also automatically sent to the designated client email.
  • Older backup files on the VPS are automatically removed based on the configured retention period; backup activities are logged for monitoring and verification.
  • If restoration is required, the ZIP backup is extracted and restored to the appropriate MongoDB environment using the standard process (mongorestore).
  • Website backup: the application source code and deployment files are maintained in the code repository and server environment; in the event of a server or deployment failure, the application can be redeployed from these.

Section 9
Security Testing / Vulnerability Assessment
Before delivery, application-level security checks were performed for the Next.js website and CMS. The checks included:
  • Authentication and admin access control testing.
  • Authorization checks for protected CMS and API functionality.
  • API endpoint access testing.
  • Input validation and invalid-input testing.
  • Basic Cross-Site Scripting (XSS) checks.
  • Verification that database credentials and sensitive configurations are not exposed through the frontend.
  • Environment variable and secret configuration review.
  • MongoDB database access configuration review.
  • HTTPS and secure communication verification.
  • CMS create, update, and delete authorization checks.
  • Basic production and server configuration review.
No critical security issues were identified during the application-level checks performed prior to delivery.
Please note that a formal third-party penetration test or comprehensive professional vulnerability assessment was not included in the agreed project scope. The above represents the application-level security testing and verification carried out by our team before delivery.
