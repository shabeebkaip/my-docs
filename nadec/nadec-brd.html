1. Project Overview

Rebuild nadec.com covering three RFP scope items:

  1. Website Design & Development — UX/UI, design system, front-end + back-end, CMS, bilingual AR/EN
  2. Annual Website Support & Maintenance — 2 years, security patching, SLA-tiered support
  3. SEO — technical, on-page, Core Web Vitals, off-page, content strategy, Local SEO

Not a greenfield build: the current site is live, Drupal-based, and carries real content volume (investor documents, governance filings, multilingual news, product catalog) that must migrate cleanly.

4. Current State

Verified via live crawl/audit, not assumption.

  • Stack: Drupal 9/10, custom theme (nadec_theme), Cloudflare CDN/WAF. TLS and security headers already correctly configured — preserve, don't regress.
  • Performance: Mobile Lighthouse Performance 44/100, mobile LCP 4.8s (fail), desktop CLS 0.62 (fail), TTFB fails on both platforms. Homepage payload ~7.4MB, with 3 animated GIF stat-counters accounting for ~2.9MB of that. No WebP/AVIF anywhere.
  • i18n: Root domain always serves Arabic regardless of Accept-Language. Arabic pages link hreflang to English; English pages do not link back (one-directional gap). No x-default.
  • SEO baseline: Zero structured data sitewide. Sitemap lists only ~37 URLs against a real catalog of ~130+ combined items. 4 confirmed duplicate-URL pairs. 1 insecure HTTP video embed. Missing SPF record.
  • Content gaps: 0/141 sampled products have nutrition/ingredient/SKU data. Recipes/Departments/Initiatives pages render fully empty despite existing UI scaffolding.
  • Accessibility: Strengths to preserve — font-size toggle, dark mode, voice toolbar, labeled contact form. Gaps — multiple <h1>s per page, missing ARIA landmarks.
  • Local/branches: NAP data + branches page exist, but the map is a JS-rendered widget exposing only the HQ record to crawlers — full branch network needs headless (Playwright) enumeration before schema work.
  • Security note: Careers page currently leaks an internal employee email via a raw Outlook Safelinks URL — quick-win fix.

5. Design Requirements

Direction: "Grounded Premium" — chosen for NADEC's brand equity as a trusted, 45-year-old publicly listed institution serving both mainstream households and investors, not a generic "modern and clean" brief.

  • Real over synthetic: actual farm and plant photography/video — drone footage of dairy farms, real processing-line footage — as the primary visual language, not stock imagery or default synthetic 3D.
  • One 3D moment, not a 3D site: a single, purpose-built "farm to carton" 3D/scroll hero on the homepage only. Every other page uses photography, CSS parallax, and scroll-reveal — no added Core Web Vitals risk beyond that one hero.
  • Brand palette carried forward: NADEC's existing blue (#2B338C / #001971) and green (#7FBC42) formalized as governed design tokens, not replaced.
  • Typography carries "premium": a confident type system — warm/humanist serif for headlines, clean grotesque for UI/body — paired equivalently for Arabic and Latin scripts.
Performance-safe by design. The 3D hero is capability-gated: mobile and low-bandwidth devices receive a static art-directed image or a short sub-2MB video loop instead of the WebGL scene. The 3D bundle is never requested on a device that fails the capability check, and the hero is never the LCP-blocking element.

Explicitly avoided: a WebGL-playground site (3D scoped to exactly one hero); a novelty/challenger tone (NADEC is the incumbent, not the disruptor); any palette change (existing brand colors are formalized, not discarded).

Full curated reference gallery and technical guardrails (draw-call budget, off-main-thread shader compilation, compressed assets) are maintained in the companion design-direction document.

8. Technical Architecture Decisions

8.1 Technology Stack — Decided

Confirmed: full platform migration off Drupal to a MERN stack with Next.js — MongoDB (data store), Express/Node.js (API layer), React via Next.js (front-end, SSR/ISR rendering). This is a full rebuild, not a Drupal-foundation rebuild — the investor-document library, multilingual content, and webform infrastructure are re-modeled natively in MongoDB rather than carried over from Drupal's content system.

CMS layer: MERN has no built-in content-editing admin, so a custom Node/Express-backed admin interface (or an integrated headless CMS connected to MongoDB) is required to meet the "staff-editable without developer involvement" requirement (Scope Item 07). This choice — fully custom-built admin vs. headless CMS on top of MongoDB — should be confirmed at kickoff (Section 12).

8.2 Front-End Delivery

Next.js app with component-driven architecture against a governed design-token system (color/type-scale/spacing). SSR/ISR used for SEO-sensitive pages (product, news, investor documents) so content is crawlable without a client-side render wait. Image pipeline uses Next.js's built-in image optimization for WebP/AVIF with responsive srcset, replacing the current unoptimized Drupal image-styles output.

8.3 Internationalization Fix

Reciprocal hreflang="ar"/hreflang="en" plus x-default across every paired AR/EN template, generated automatically from the CMS content-translation relationship — not hand-maintained per page.

8.4 CDN & Edge

Cloudflare configuration retained. Static asset cache headers corrected from 4h max-age to long-lived immutable for content-hashed bundles.

8.5 Hosting & Backend Response Time

TTFB is a server/backend issue, not front-end — on the new stack this means profiling Node/Express API response time and MongoDB query performance, plus using Next.js ISR/caching so high-traffic templates aren't rendered fresh on every request. Correct static-asset cache headers. Requires hosting/infra access during remediation (Section 13).

8.6 Domain Consolidation

Legacy /index.php/en/X duplicate URLs (meat/about/feed/juice confirmed) must resolve via canonical/redirect, not remain as duplicate-content pairs.

9. SEO / Technical Requirements

  • Structured data: LocalBusiness/Organization schema referencing fully-enumerated branch data (post Playwright enumeration).
  • Sitemap regeneration: CMS-driven, both language versions per page, first-class cross-annotated entries.
  • Fix 4 broken 404 assets, 1 insecure HTTP video embed, missing SPF record.
  • Local SEO: confirm current Google Business Profile status with NADEC first, then build/optimize multi-location GBP (HQ, processing plants, branch network). Enforce NAP consistency across GBP, site, social, directories.
  • Off-page: current backlink profile (3,426 backlinks / 852 referring domains) has spam anchor text and authority concentrated on a secondary microsite, not nadec.com — flag as risk needing full backlink-tool review before final scoping.
  • Caution: do not overstate the ISO 42001 AI-governance angle in AI-search-visibility copy — homepage ISO mentions may reference food-safety certification, not AI governance. Confirm with NADEC before using that narrative.

10. Content Migration Requirements

  • All investor-document PDF URLs preserved 1:1 — broken investor links are not acceptable.
  • Product/nutrition/SKU data entry requires NADEC quality/regulatory team input — development delivers CMS structure and content-entry support, not regulatory sign-off on claims.
  • Content touching investor disclosures, governance documents, or regulated product/nutrition claims routes through NADEC's own compliance sign-off workflow before publish — build the CMS workflow to support that gate, don't bypass it.

12. Assumptions & Constraints

  • Nutrition, ingredient, and SKU-level product content is authored with input from NADEC's quality/regulatory team — development provides CMS structure and content-entry support, not regulatory sign-off on claims.
  • Technology stack is decided (MERN + Next.js, full migration off Drupal). The CMS-admin approach underneath it (custom-built vs. headless-on-MongoDB) and e-commerce scope (full store vs. store-locator vs. B2B portal) are confirmed at kickoff — both materially affect timeline and effort.
  • Hosting/infrastructure access sufficient to profile and remediate TTFB is made available during the performance-remediation phase.
  • Content touching investor disclosures, governance documents, or regulated claims routes through NADEC's own compliance/regulatory sign-off before publication.
  • A ~14-week design-and-build timeline is a planning baseline for a public-company site of this content depth; final scheduling is confirmed once the CMS-path and e-commerce-scope decisions are settled at kickoff.
  • Off-page backlink remediation requires licensed tool access (Ahrefs/SEMrush) not yet confirmed as available.

13. Open Decisions Required From Client

  1. CMS admin approach: fully custom-built Node/Express admin interface vs. a headless CMS integrated on top of MongoDB. (Technology stack itself — MERN + Next.js — is decided; this is the remaining CMS-layer question underneath it.)
  2. E-commerce scope: full store / store-locator / B2B portal / none.
  3. Hosting/infra access: sufficient access granted during performance-remediation phase to profile and fix TTFB on the Node/MongoDB backend.
  4. GBP/licensed SEO-tool access for off-page/backlink review.
These four decisions materially change timeline and effort — development should not start against assumptions on any of them.

15. Out of Scope (This Phase)

  • Regulatory/nutrition claim sign-off (client-owned).
  • Full backlink remediation execution (data gap, needs licensed tool access first).
  • Large-scale content authoring beyond CMS scaffolding (client data-entry responsibility, with support).
  • Large-scale content migration, bulk rewrites, new catalog categories, or full-catalog-scale nutrition/ingredient data entry beyond the support contract's routine-update allowance (change-request territory).

16. Glossary

TermMeaning
CWV — Core Web VitalsGoogle's user-experience performance metrics (LCP, CLS, and related), used as an SEO ranking signal.
LCP — Largest Contentful PaintTime until the largest visible element on a page finishes rendering; a page-load speed metric.
CLS — Cumulative Layout ShiftMeasure of unexpected visual layout movement during page load.
TTFB — Time to First ByteServer response time between request and the first byte of response — a backend/hosting metric.
hreflangHTML attribute telling search engines which language/region version of a page to serve.
RTLRight-to-left text direction, required for Arabic layout.
WCAGWeb Content Accessibility Guidelines — the accessibility standard being targeted (2.2).
GBPGoogle Business Profile — the listing that powers local search/maps presence.
NAPName, Address, Phone — consistency of this data across the web is a local-SEO ranking factor.
Structured data / schemaMachine-readable markup (e.g. LocalBusiness) that helps search engines understand page content.

SKUStock Keeping Unit — a unique product identifier.
