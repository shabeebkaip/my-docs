1. Project Overview

The RFP defines one mandatory deliverable and one optional deliverable — a structural requirement, not a phasing preference:

  1. Deliverable 1 — Website Design MANDATORY · FIRM PRICE
    Discovery, IA/UX, bilingual AR/EN high-fidelity design, design system, interactive prototypes, and production-ready static front-end templates (HTML5/CSS3/JS + Bootstrap or Tailwind). No CMS, backend application, or database.
  2. Deliverable 2 — Umbraco CMS Implementation OPTIONAL · SEPARATE PRICE
    Proceeds only on NADEC's formal written activation. Full Umbraco CMS on Microsoft .NET/SQL Server, built on the approved Deliverable 1 templates: content modeling, bilingual culture variants, editorial workflow, legacy migration, SEO, testing, deployment, training, hypercare.

Not a greenfield build: the current site (nadec.com) is live on Drupal and carries real content volume (investor documents, governance filings, multilingual news, product catalog). Drupal is the legacy system being migrated from — not the target platform. If Deliverable 2 is activated, the target CMS is Umbraco, per the RFP's explicit technology mandate (Section 8.2).

Correction note. An earlier draft of this BRD assumed CMS + migration + 2-year support were core, undifferentiated scope, and separately assumed a Drupal-foundation rebuild (then a MERN/Next.js migration) as the target platform. Neither matches the RFP as issued. This revision aligns strictly to the RFP's own Deliverable 1 / Deliverable 2 split and its Umbraco/.NET/SQL Server mandate.

4. Current State

Verified via live crawl/audit, not assumption.

  • Stack (legacy, migrated from): Drupal 9/10, custom theme (nadec_theme), Cloudflare CDN/WAF. TLS and security headers already correctly configured — preserve, don't regress, if/when D2 goes live.
  • Performance: Mobile Lighthouse Performance 44/100, mobile LCP 4.8s (fail), desktop CLS 0.62 (fail), TTFB fails on both platforms. Homepage payload ~7.4MB, with 3 animated GIF stat-counters accounting for ~2.9MB of that. No WebP/AVIF anywhere.
  • i18n: Root domain always serves Arabic regardless of Accept-Language. Arabic pages link hreflang to English; English pages do not link back. No x-default.
  • SEO baseline: Zero structured data sitewide. Sitemap lists only ~37 URLs against a real catalog of ~130+ combined items. 4 confirmed duplicate-URL pairs. 1 insecure HTTP video embed. Missing SPF record.
  • Content gaps: 0/141 sampled products have nutrition/ingredient/SKU data. Recipes/Departments/Initiatives pages render fully empty despite existing UI scaffolding.
  • Accessibility: Strengths to preserve — font-size toggle, dark mode, voice toolbar, labeled contact form. Gaps — multiple <h1>s per page, missing ARIA landmarks.
  • Local/branches: NAP data + branches page exist, but the map is a JS-rendered widget exposing only the HQ record to crawlers — full branch network needs headless (Playwright) enumeration before schema work (D2).
  • Security note: Careers page currently leaks an internal employee email via a raw Outlook Safelinks URL (D2 fix — requires a live/editable page).

These findings are inputs to Deliverable 1 design decisions and become live remediation targets under Deliverable 2 if and when it is activated.

5. Design Requirements D1

Direction: "Grounded Premium" — chosen for NADEC's brand equity as a trusted, 45-year-old publicly listed institution serving both mainstream households and investors, not a generic "modern and clean" brief.

  • Real over synthetic: actual farm and plant photography/video — drone footage of dairy farms, real processing-line footage — as the primary visual language, not stock imagery or default synthetic 3D.
  • One 3D moment, not a 3D site: a single, purpose-built "farm to carton" 3D/scroll hero on the homepage only, built as a static/interactive front-end asset. Every other page uses photography, CSS parallax, and scroll-reveal.
  • Brand palette carried forward: NADEC's existing blue (#2B338C / #001971) and green (#7FBC42) formalized as governed design tokens, not replaced.
  • Typography carries "premium": a confident type system — warm/humanist serif for headlines, clean grotesque for UI/body — paired equivalently for Arabic and Latin scripts.
Performance-safe by design. The 3D hero is capability-gated at the static template level: mobile and low-bandwidth devices receive a static art-directed image or a short sub-2MB video loop instead of the WebGL scene. The hero must never be the LCP-blocking element in the delivered templates.

Explicitly avoided: a WebGL-playground site; a novelty/challenger tone (NADEC is the incumbent, not the disruptor); any palette change.

Per RFP §2.1: WCAG 2.1 AA design considerations apply at the design/template level regardless of whether Deliverable 2 is activated. All visual assets and fonts must be licensed, disclosed, and transferable to NADEC without vendor lock-in.

Full curated reference gallery and technical guardrails are maintained in the companion design-direction document.

8. Technical Architecture

8.1 Deliverable 1 Front-End Stack — Open Decision

RFP mandates HTML5/CSS3/JavaScript with either the latest stable Bootstrap or Tailwind CSS version, approved by D&T. Recommend Tailwind for the governed-design-token/component approach in Section 5, but D&T approval is required before build starts (Section 13.1).

8.2 Deliverable 2 CMS Platform — RFP-Mandated, Capability Open Risk

RFP mandates Umbraco (latest stable, LTS preferred) on Microsoft .NET runtime + SQL Server for Deliverable 2 — fixed by the client, not a recommendation we can substitute. Drupal and any other CMS/stack do not satisfy Appendix A compliance. Open risk, unconfirmed: whether the delivery team has direct Umbraco/.NET/SQL Server production experience to stand behind the RFP §6.1 vendor-qualification claim and Appendix A compliance line. Must be resolved — confirmed in-house, confirmed via a named subcontractor (disclosed per RFP §7.1), or the compliance matrix marks Deliverable 2 "N" and the bid proceeds on Deliverable 1 only — before this BRD or the proposal are finalized for submission.

8.3 Internationalization

Deliverable 1: equal-quality AR RTL / EN LTR templates, component mirroring. Deliverable 2: reciprocal hreflang="ar"/hreflang="en" + x-default generated automatically from the Umbraco content-translation relationship.

8.4 CDN & Edge D2

Cloudflare configuration retained. Static asset cache headers corrected from 4h max-age to long-lived immutable for content-hashed bundles.

8.5 Hosting & Backend Response Time D2

TTFB is a server/backend issue. Profile backend rendering path, implement page-level cache warming, correct static-asset cache headers. Requires hosting/infra access during remediation (Section 13).

8.6 Domain Consolidation D2

Legacy /index.php/en/X duplicate URLs (meat/about/feed/juice confirmed) must resolve via canonical/redirect, not remain as duplicate-content pairs.

9. SEO / Technical Requirements D2

Per RFP §3.2, SEO is scoped under Deliverable 2, not Deliverable 1:

  • Structured data: LocalBusiness/Organization schema referencing fully-enumerated branch data (post Playwright enumeration).
  • Sitemap regeneration: CMS-driven, both language versions per page, first-class cross-annotated entries.
  • Fix 4 broken 404 assets, 1 insecure HTTP video embed, missing SPF record.
  • Local SEO: confirm current Google Business Profile status with NADEC first, then build/optimize multi-location GBP. Enforce NAP consistency across GBP, site, social, directories.
  • Off-page: current backlink profile (3,426 backlinks / 852 referring domains) has spam anchor text and authority concentrated on a secondary microsite, not nadec.com — flag as risk needing full backlink-tool review before final scoping.
  • Caution: do not overstate the ISO 42001 AI-governance angle in AI-search-visibility copy — homepage ISO mentions may reference food-safety certification, not AI governance. Confirm with NADEC before using that narrative.
Note: if NADEC activates Deliverable 1 only, none of the above SEO work is in scope or priced — it depends entirely on a live CMS.

10. Content Migration Requirements D2 only

  • All investor-document PDF URLs preserved 1:1 — broken investor links are not acceptable.
  • Product/nutrition/SKU data entry requires NADEC quality/regulatory team input — vendor delivers CMS structure and content-entry support, not regulatory sign-off on claims.
  • Content touching investor disclosures, governance documents, or regulated product/nutrition claims routes through NADEC's own compliance sign-off workflow before publish.
  • At least one trial migration required before final cutover, with migration reports, counts, exceptions, and reconciliation (RFP §3.1).

12. Assumptions & Constraints

  • Nutrition, ingredient, and SKU-level product content is authored with input from NADEC's quality/regulatory team (D2).
  • Bootstrap-vs-Tailwind (D1) and Umbraco/.NET delivery-capability (D2) are both open and must be resolved before final commercial commitment (Section 13).
  • E-commerce is treated as out of RFP scope unless NADEC explicitly requests it.
  • Hosting/infrastructure access sufficient to profile and remediate TTFB is made available during the D2 performance-remediation phase, if activated.
  • Content touching investor disclosures, governance documents, or regulated claims routes through NADEC's own compliance/regulatory sign-off before publication.
  • A design-and-build timeline for Deliverable 1 is proposed separately from Deliverable 2's timeline, per RFP §6.2.
  • Off-page backlink remediation (D2) requires licensed tool access (Ahrefs/SEMrush) not yet confirmed as available.
  • NADEC may award Deliverable 1 only, and activate Deliverable 2 later through written request, at its sole discretion (RFP §7.2).

13. Open Decisions Required Before Submission

  1. Bootstrap vs. Tailwind CSS for Deliverable 1 — recommend Tailwind, requires D&T approval.
  2. Umbraco/.NET/SQL Server delivery capability — confirm in-house capability, or name a disclosed subcontractor, or bid Deliverable 1 only. Currently unresolved.
  3. E-commerce scope — confirm with NADEC whether it is wanted at all; if so, it is additional scope outside this RFP's deliverables.
  4. Hosting/infra access — sufficient access granted during D2 performance-remediation phase to profile and fix TTFB.
  5. GBP/licensed SEO-tool access (Ahrefs/SEMrush) for off-page review, if D2/SEO is activated.
  6. Submission logistics — the RFP document itself leaves Submission Contact, Email, and Deadline blank; obtain actual values from NADEC Procurement before finalizing the proposal package.
  7. Three client references and subcontractor disclosures required for RFP §6.1/6.2 — confirm which reference projects to use.
These materially change scope, technology commitments, and pricing — do not finalize the proposal against assumptions on any of them.
