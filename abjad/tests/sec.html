Security & Role Isolation

Cross-cutting: role isolation between teacher/school/admin, team-role permission enforcement, and session lifetime. Test both UI hiding AND direct URL/API access.

IDPriTest case · steps · expectedStatusNotes
SEC-01Teacher cannot reach school routes. Logged in as teacher, navigate to /school/dashboard, /school/candidates. Expect: blocked / redirected; API returns 401/403, no school data leaked.
SEC-02School cannot reach teacher-only routes. As school, hit teacher-only endpoints. Expect: blocked / 403.
SEC-03Non-admin cannot reach admin app/API. As teacher/school, open admin :3001 and call admin endpoints. Expect: denied; no admin data.
SEC-04Direct-object access. As teacher A, request teacher B's application/offer by ID; as school X, request school Y's data by ID. Expect: 403/404 — no cross-tenant leakage.
SEC-05Viewer write-block at API. As a Viewer team member, call a write endpoint (post job / send offer) directly. Expect: rejected even though UI hides the button.
SEC-06Interviewer scope. As Interviewer, attempt to post a job / extend an offer via API. Expect: 403.
SEC-07Session expiry + refresh. Stay idle until the access token would expire (~15 min) then act. Expect: silent refresh keeps session, OR clean redirect to login with ?next=.
SEC-08Deleted/suspended user session. While a user is logged in, have admin suspend/delete them; user then acts. Expect: /me/refresh checks reject; user is logged out.
SEC-09Auth redirects. Logged-in teacher visits /login → /dashboard; school → /school/dashboard. Unauthenticated visiting a protected page → login. Expect: correct redirects.
SEC-10Cookie hardening. Inspect the session cookie. Expect: HttpOnly + Secure attributes (__Host- prefix); not readable from JS.
