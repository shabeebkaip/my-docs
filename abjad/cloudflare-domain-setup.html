Cloudflare sits between visitors and our server — it manages the domain, encrypts traffic, and hides the server's real IP address for security. The server then routes each request to the right application.

Why Cloudflare

Three Jobs, One Free Service

📖

The address book (DNS)

Cloudflare translates your domain name into the server's location — like a phone book for the internet. When we ever move or upgrade servers, we change one entry and visitors notice nothing.

🔒

The padlock (SSL)

Every visit is encrypted — the browser shows the padlock and "https". Cloudflare issues and renews this certificate automatically, for free, forever.

🎭

The mask (IP hiding)

The server's real address stays secret. Attackers who want to hit the server directly can't find it — they only ever see Cloudflare, which is built to absorb attacks.

The Difference It Makes

With Cloudflare vs. Without

Without Cloudflare

  • Server's real address is public — anyone can target it directly
  • SSL certificate must be installed and renewed manually on the server
  • Attack traffic hits your server at full force
  • Moving servers means DNS changes visitors may feel

With Cloudflare (free plan)

  • Real server address hidden behind Cloudflare's network
  • SSL issued and renewed automatically — always valid
  • Common attacks absorbed before they reach the server
  • Server changes are invisible to visitors

How We Set It Up

Five Steps to Go Live

  1. Choose & purchase the domain

    You pick the name; it can be registered at any registrar (~$10–15/year).

  2. Add the domain to Cloudflare (free plan)

    Cloudflare takes over as the domain's address book (DNS).

  3. Point Cloudflare at the new Amazon server

    One DNS record connects the domain to the new t3a.large server — with masking switched on, so the server's real address stays hidden.

  4. Switch on SSL

    The padlock appears — all traffic between visitors and the platform is encrypted.

  5. Verify everything end to end

    We test the website, admin dashboard, and API through the domain before calling it live.
