First, The Basics

The Three Pieces, In Plain Words

No jargon — here's what each piece actually is and why the platform can't go live without it.

🌐

The Domain — your address

The name people type to reach you, like abjadteach.com. Without it, the platform is only reachable by a raw number (an IP address) that nobody can remember — and browsers flag as untrustworthy. You own it, registered in your name, renewed yearly like a trade licence.

🛡️

Cloudflare — your gatekeeper

A global security company that sits between the internet and your server. Roughly 1 in 5 of all websites route through it — including banks and governments. Every visitor passes its checkpoint before ever touching your server.

🖥️

The Server — your building

The new dedicated Amazon server (t3a.large) where the three applications actually live: the public website, the admin dashboard, and the backend engine. Covered in detail in the separate infrastructure report.

A Closer Look

How "Hiding the Server" Actually Works

This is the piece you specifically asked about — here's exactly what changes:

❌ Without masking

😈 Attacker
→
looks up your domain
→
sees the server's real address

The domain points straight at the server, so its real address is public. Attackers can bypass every protection and hit the server directly — flooding it, probing it for weaknesses, or targeting the applications on it.

✅ With Cloudflare masking

😈 Attacker
→
looks up your domain
→
sees only Cloudflare 🛡️

The domain points at Cloudflare, and Cloudflare quietly forwards clean traffic to the server. On top of that, we configure the server's firewall to only accept traffic coming from Cloudflare — so even someone who somehow discovered the real address would be turned away at the door.

The Difference It Makes

Day-to-Day: With Cloudflare vs. Without

Without Cloudflare

  • Server's real address is public — anyone can target it directly
  • SSL certificate must be installed and renewed manually on the server — if a renewal is missed, visitors see a security error
  • Attack and junk traffic hits your server at full force, and you pay Amazon for that bandwidth
  • Site speed depends entirely on distance to Frankfurt
  • Moving or upgrading servers requires DNS changes visitors may feel
  • No visibility into traffic or threats without extra tools

With Cloudflare (free plan)

  • Real server address hidden behind Cloudflare's global network
  • SSL issued and renewed automatically — always valid, zero maintenance
  • Attacks and junk traffic absorbed before they reach (or bill) the server
  • Site loads fast worldwide via 300+ locations
  • Server changes are invisible to visitors — one entry updated
  • Built‑in dashboard: visits, countries, threats blocked

How We Set It Up

Five Steps to Go Live

Once the domain name is confirmed, the whole layer is typically live within a day:

  1. Choose & purchase the domain ~30 min

    You pick the name; we register it (or you register it — either way it's owned by Abjad). ~$10–15/year.

  2. Add the domain to Cloudflare ~1 hour

    A free Cloudflare account is created in Abjad's name, and the domain's address book (DNS) moves under Cloudflare's management.

  3. Point Cloudflare at the new Amazon server ~15 min

    One DNS record connects the domain to the new t3a.large server — with masking switched on from minute one, so the real address is never exposed. We also lock the server's firewall to accept traffic only from Cloudflare.

  4. Switch on SSL automatic

    Cloudflare issues the certificate — the padlock appears and all traffic is encrypted end to end. Renewal is automatic forever.

  5. Verify everything end to end ~2 hours

    We test the website, admin dashboard, and API through the real domain — on desktop and mobile — before calling it live.

Questions You Might Have

Straight Answers

Who owns the domain and the Cloudflare account?
You do — both are created in Abjad's name, with your email as the owner. We only hold working access to manage them for you. If we ever part ways, everything stays yours.
Does Cloudflare see or store our data?
Traffic passes through Cloudflare encrypted, the same way it passes through any internet provider. Cloudflare doesn't store your platform's data — your database lives on your server and MongoDB Atlas. This is the same arrangement used by banks, universities, and government sites worldwide.
What if Cloudflare itself has an outage?
Rare, but honest answer: if Cloudflare's network has a major outage, the site would be unreachable for that period — along with a large portion of the internet (their outages make the news precisely because so much depends on them). Their reliability track record is stronger than what a single server could achieve alone, and the trade-off strongly favors having the protection.
Are we locked in? Can we leave Cloudflare later?
No lock-in. The domain is yours, and DNS can be moved to any other provider in under an hour. Cloudflare is the default choice because the free tier is the most generous in the industry — but it's a plug, not a weld.
Can we have email on the domain (e.g. info@abjadteach.com)?
Yes — the domain supports professional email through services like Google Workspace (~$6/user/month) or Zoho Mail (free tier available). It's a separate small setup we can add anytime; it doesn't affect anything in this document.
Why not just use the paid Cloudflare plan for "better" security?
The free plan already includes the protections that matter at this stage: SSL, DDoS absorption, IP masking, and CDN. Paid tiers add tools like advanced firewall rules and image optimization — useful at much larger scale, and easy to switch on later if ever needed. Starting free is not a compromise; it's the right size.
Does this affect the existing application on the old server?
Not at all. This entire layer sits in front of the new server only. The existing application and its server continue exactly as they are today.
