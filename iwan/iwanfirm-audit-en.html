Executive summary

The short version

Good news first: the website is not hacked. No malware, injected spam, or defacement was found, and the site is not blocked by Google or any major security vendor. The connection is secure, and there is active protection against automated attacks.

There are, however, three things worth fixing. None are emergencies, but addressing them will make the site noticeably safer, faster, and easier to find on Google — and most of the high-impact fixes are quick.

1

Security hardening is weak. The site is clean, but it is missing standard protective settings that every modern website should have. This doesn't mean it's compromised — it means the "locks" could be stronger.

2

It is slow to respond. The server takes about 2.2 seconds just to begin loading a page, where under half a second is the target. The most likely cause is that page caching isn't switched on.

3

Some SEO essentials are missing. The technical foundation is solid, but a few basics (page heading, title, description, local business details) are holding back its Google ranking.

01 · Security

Is the site compromised? No. Could it be hardened? Yes.

What's working well

No malware · not blocklistedPass

An external malware scan (Sucuri, 7 Oct 2026) came back clean — no malicious code, spam injection, or defacement. The domain is not flagged by Google Safe Browsing or other vendor blocklists. Overall third-party rating: B.

Secure connection (HTTPS/TLS)Pass

Valid SSL certificate (issued by SSL.com, valid until 23 Apr 2027), served over HTTP/2 with no insecure "mixed content". TLS configuration rated A.

Active bot protectionPass

A host-level firewall (BitNinja) presents a "One moment, please…" verification to automated visitors, which blocks most scanners and brute-force bots — it even blocked parts of our own automated scan, which is a good sign.

Needs attention

Missing security headersMedium

The site scores an F on securityheaders.com: all six standard protective headers are absent — HSTS, Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Referrer-Policy and Permissions-Policy. Their absence leaves the site more exposed to clickjacking, content-type attacks, and HTTPS downgrade.

Fix: add the headers via LiteSpeed/.htaccess, a WordPress security plugin, or a Cloudflare layer. Moves the grade from F toward A with no visible change for users.

Login & account hardening (to confirm)Medium

Standard WordPress attack surfaces (the login page, XML-RPC, and REST-API user listing) could not be fully tested from outside because the bot firewall intercepted the checks. These should be confirmed and locked down.

Fix: enforce two-factor authentication and strong passwords for all admins, limit login attempts, disable XML-RPC if unused, and block user-enumeration. Best verified with admin access (see below).

No application-level firewall rulesMedium

Bot protection exists at the host, but there's no application firewall / Content-Security-Policy filtering requests to the WordPress app itself.

Fix: a cloud WAF/CDN (e.g. Cloudflare) adds request filtering, the missing headers, and a speed boost in one step.

Software version disclosureLow

The pages publicly advertise the WordPress and server software in use (the generator tag reports WordPress 7.1.3), which helps attackers fingerprint the site. The reported version is also unusually high — worth confirming it is genuine and fully patched.

Fix: remove the generator meta tag and keep WordPress core, the Blocksy theme, and all plugins on their latest patched versions.

Contact form (Forminator)Low

The contact form runs on the Forminator plugin — a common target for spam and probing. Form plugins need to be kept current and protected.

Fix: ensure CAPTCHA or honeypot spam protection is enabled and keep Forminator updated.

OCSP stapling not enabledLow

A minor TLS optimization that speeds up certificate validation is switched off.

Fix: enable OCSP stapling at the server (small, optional tuning).

The headline issue is the ~2.2 second server response time. On a LiteSpeed server with caching enabled, a page should return in under 0.2s — so the most likely cause is that full-page caching isn't active. First-time visitors may also briefly see the "One moment, please…" verification screen, which adds to the wait.

What's working well

  • GZIP compression is enabled (pages are sent compressed).
  • Modern HTTP/2 protocol is in use.
  • A current, well-maintained theme (Blocksy) and up-to-date jQuery.

What's slowing it down

No full-page cachingHigh impact

The 2.2s response suggests each page is being rebuilt from scratch on every visit.

Fix: enable LiteSpeed Cache (free, built for this exact server). This is the single biggest win — it should cut response time to well under half a second.

Unoptimized imagesMedium

Team photos are full-size images uploaded directly from WhatsApp, not resized or served in a modern format (WebP).

Fix: compress and convert images to WebP, serve them at display size, and enable lazy-loading.

Many separate CSS/JS filesMedium

The homepage loads roughly 11 stylesheets and 16 scripts, several of which block the page from rendering.

Fix: combine, minify and defer non-essential CSS/JS — LiteSpeed Cache can do this automatically.

No CDNLow

Content is served from a single origin, so distant visitors wait longer.

Fix: a CDN such as Cloudflare improves global speed and also delivers the missing security headers and firewall in one move.

Note: a Google PageSpeed (Lighthouse) score could not be captured — Google's public testing service was rate-limiting requests at scan time. The figures above are from real-page load timing measured in the browser.

03 · SEO

Good foundation, a few key gaps

Needs fixing

No main heading (H1) on the homepageHigh

The homepage has 19 sub-headings but no top-level H1 — a core signal Google uses to understand the page.

Fix: add one clear, keyword-rich H1, e.g. a line naming the firm as a law firm in Jeddah.

Weak page title & descriptionMedium

The homepage title is effectively just "Home — [firm name]", and the meta description is only three words. Neither contains the search terms clients would use (e.g. محاماة / محامي / جدة).

Fix: rewrite the title to include the practice and city, and write a ~150-character description with a clear call to action.

No local-business structured dataMedium

There's no LegalService/LocalBusiness schema telling Google the firm's name, address, phone, location and hours — important for a local law firm to appear in map and local results.

Fix: add LegalService schema (with full address + geo-coordinates) and set up / verify a Google Business Profile.

Images missing alt textLow

6 of 9 homepage images have no alt text, which hurts image search and accessibility.

Fix: add descriptive alt text to all images.

Thin contentLow

The blog and news sections are present but empty, so the site has little indexable content to rank for.

Fix: publish articles on common legal questions to build topical authority and capture search traffic.

Working well

  • Open to search engines (indexable), with a correct robots.txt and an XML sitemap already in place.
  • Canonical tag and Open Graph / Twitter social-sharing tags are configured.
  • An SEO plugin is active and generating the metadata framework.
  • The site is mobile-responsive.
  • Arabic and English locales are declared — if a full English version exists, add hreflang tags to link them.

Next step

For a complete review, request WordPress admin access

Why we need admin credentials

This audit was done entirely from the outside. Several important checks can only be made from inside the WordPress dashboard — and the site's bot protection deliberately blocks external probing (a good thing, but it limits how deep an outside scan can go). With a temporary admin login, we can verify and report on:

  • Exact WordPress, theme and plugin versions — and whether any have known vulnerabilities or are abandoned.
  • All user accounts and their roles (to rule out any rogue or unused admin accounts).
  • Login security settings — whether two-factor and login-attempt limits are in place.
  • Backup status and file integrity (is there a working, recent backup?).
  • Caching, security and SEO plugin configuration — so fixes can be applied correctly.
  • Pending updates and overall database/site health.

We recommend sharing access securely: a dedicated admin account created for the review, with two-factor enabled, and the password changed once the review is complete.

Methodology. Findings are based on in-browser inspection of the live site (response timing, headers, page structure and resources), securityheaders.com, Sucuri SiteCheck, and robots.txt / sitemap checks, on 7 October 2026.
Limitation. The site's bot-protection firewall blocked automated probing of some internal endpoints; items marked "to confirm" are best verified with admin access.
