Recommended Architecture

One backend, one command center

Website, mobile app, and every future product should read and write through the same backend — not five separate builds on five separate demo subdomains. One diagram, animated to show it's live traffic, not a static org chart.

Client → Gateway traffic Gateway → microservice calls Service → data reads/writes

Today, as far as we can see

  • Rent and Event App demos live on two separate, disconnected Hostinger subdomains
  • No admin/ops dashboard found — no way to manage activities, facilities, or users in one place
  • Every new product looks like a new build from scratch, not a new service on shared infrastructure

One backend, one command center

  • Website, mobile app, and Command Center all call the same API Gateway — build a feature once, it works everywhere
  • Command Center gives SkillVera's own team one dashboard for activities, facilities, bookings, users, and content across every product
  • Adding Training Centers or XR/AI as real software later means adding one microservice, not standing up a new app from zero

Proposed Engagement

Annual Maintenance & Feature Delivery

We recommend two tracks that run side by side: an Annual Maintenance Contract keeping the platform secure, stable, and current, and a Feature Delivery track that turns the roadmap above into shipped work — scoped and quoted per initiative so you always know what you're paying for.

What the AMC covers

1

Security & compliance monitoring

Encryption, PDPL alignment, and a recurring vulnerability pass — starting with the data-encryption gap flagged above.

2

Bug fixes on an SLA

Defined response and resolution times for both the app and the website, not best-effort.

3

Store & platform upkeep

App Store/Play Console health, OS compatibility, dependency and library updates.

4

Performance & uptime monitoring

Core Web Vitals, crash reporting, and alerting — so issues are caught before users report them.

5

Monthly health report

One dashboard-style report covering security, performance, SEO, and open items — no chasing status.

6

Priority support channel

A direct line to the team already familiar with your codebase, not a fresh ticket queue each time.

How a feature request moves

  1. Submit — a new idea from either side, mapped against the roadmap above or raised fresh.
  2. Scope & estimate — we return effort, cost, and dependencies within an agreed turnaround.
  3. Approve — you sign off scope and cost before any build work starts.
  4. Build & QA — developed, then independently tested against acceptance criteria.
  5. Release & review — shipped, monitored, and closed out in the next monthly report.
