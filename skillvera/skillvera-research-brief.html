Where It Stands Today

The honest gap

Not a formal QA audit — surface-level findings from public site/store review only. The good news: none of this is architecturally hard to fix. It's a design-and-craft gap, not a technology gap.

Security / Compliance

Collected user data is unencrypted

Google Play's Data Safety section explicitly states data isn't encrypted, while the app collects financial and health data linked to identity. Worth a real security review given PDPL obligations in KSA.

Broken flow

Both product "Demo" links are dead

Not just Rent — every "Demo" CTA on the Products page is broken. SkillVera Rent and Event App each link to their own Hostinger-hosted subdomain (lightpink-goose-814046 / lightgray-pony-732195.hostingersite.com), and both return error pages. Two live, linked-to broken experiences on the public marketing site, not one.

Layout bug

English site renders header right-to-left

On skillvera.sa/en the logo sits on the right and the nav reads Contact → Products → Services → About → Home — mirrored as if still in Arabic. Root cause in the page source: the header nav has a hardcoded flex-row-reverse Tailwind class that isn't conditioned on locale, so it never flips back for English. One-line fix, but visible on every English page load.

Store metadata

App Store language mismatch

App Store lists "English" as the only supported language, but the actual app UI is Arabic RTL throughout.

Store metadata

Category likely wrong

Listed under "Entertainment" on both stores; content fits Health & Fitness or Lifestyle better for discoverability.

Content

Site polish gaps

CEO headshot is a placeholder icon; footer copyright reads "© Skillbera 2025" (misspelled + stale year); social icons are all disabled/non-functional in the footer.

Experience

Functional, not delightful

Every core booking/discovery flow exists, but empty states, onboarding, and visual hierarchy read as an MVP scaffold rather than a finished product — no personalization, no motion, no reason to open the app twice.

Production bug

Dev placeholder strings shipped live

Reviewed on real device screens, not store marketing shots: a location field literally reads "Location Should Here," another reads the literal word "string," and one label reads "...en is the required default locale y //" — raw i18n/dev copy shipped to production. This is the single most trust-breaking thing a user can see in a booking app.

Conversion

No visible booking CTA on the activity detail screen

The one job of a detail screen is to convert, and on the reviewed screen no enroll/book button is visible in the viewport. If it exists below the fold, that's still a failure — the primary action must never require scrolling to discover.

Consistency

Bottom navigation differs between screens

The home screen's bottom nav reads حسابي / فعالياتي / الأحصائيات / الرئيسية; the activity-detail screen shows Map / فعالياتي / جميع الفعاليات / الرئيسية — different items, different order, and "Map" left in English inside an otherwise fully Arabic RTL app. Primary navigation should be identical everywhere; this reads as two screens built by two people without a shared spec.

Comprehension

Calendar highlights have no legend

Three dates are marked with a yellow-green dot and nothing explains what it means — available slots, booked sessions, today? Decoration standing in for information.

Accessibility

Placeholder text fails contrast

Gray placeholder text inside the white login-field pills measures roughly 2.9:1 against white — WCAG AA requires 4.5:1 for body text. The rest of the login screen (white/yellow-green on indigo) actually passes comfortably; this one element doesn't.

Auth

No phone/OTP or national-ID login

Social login covers Apple, X, and Google but skips phone/OTP — the dominant consumer auth pattern in KSA — and any Nafath-style national ID option, which matters for a product selling into government and education accounts.

Credibility

Site reads as template-built, not custom

Montserrat set at heavy weights on everything, uniform fully-rounded pill buttons, a rainbow of identical pastel-gradient cards, unmodified default icon set, and generic stock photography (a person facing away from camera in the hero) — this is the exact visual signature of an AI-scaffolded Tailwind build. For a company pitching Vision 2030 institutional clients, that undercuts credibility before anyone reads a word of copy.

The Vision — Mobile

Reimagining Skv Activities

Motivation

SkillVera already built the hard part.

Auth, discovery, booking, maps, favorites, notifications, and payment-linked data are all live. That's the plumbing every great booking/fitness/learning app needs — it's the same skeleton behind the category's best experiences. What's missing is the layer that turns "functional" into "can't put it down": personalization, motion, real-time feedback, and a design system that feels premium in every screen, not just the marketing site.

Where the process broke, concretely: this went from idea straight to code with no research, IA, or shared component system in between. The evidence is on-screen — two different card/rating/nav components for the same data, no i18n QA pass before shipping (dev placeholder strings live in production), no defined empty or loading states, and no usability test session (one would have caught the missing booking CTA and the undecipherable calendar dots in an hour). Someone picked a brand color and applied it as a flat background everywhere — that's a color choice, not a visual design system.

1

Guided onboarding, not an empty inbox

Swipeable interest picker (sports, age group, location) on first launch so day-one home screen is already personalized instead of showing "no activities created."

2

A home feed that knows the user

Recommended activities by history, location, and interests — sectioned rows ("Near you," "Popular this week," "Because you joined Padel") instead of one flat list.

3

Real-time booking & live availability

Live seat counts, waitlists with auto-promotion, instant confirmation, and one-tap add-to-calendar (Apple/Google) — booking should feel as fast as buying a movie ticket.

4

Seamless in-app payments

Saved cards, mada/Apple Pay, split family bookings for parents booking multiple kids, automatic digital receipts — matches the financial data the app already declares it collects.

5

Progress & gamification tied to Talent Development

Skill-level progress bars, streaks, badges, and shareable achievement cards that connect the app directly to SkillVera's own Talent Development product line.

6

Notifications that earn their place

Session reminders, waitlist-opened alerts, personalized re-engagement nudges — not generic blasts. Every push should feel useful enough to keep enabled.

7

Map-first discovery

Clustered pins, filters by activity type/distance/price, "happening near you right now" — the maps integration already exists, it just needs a real UI on top of it.

8

Social proof & community

Photos and reviews from past participants, friend invites, and family/group accounts so parents can manage multiple children's bookings from one login.

9

Accessible & inclusive by default

VoiceOver/TalkBack labels, dynamic type support, high-contrast mode, and a genuinely polished RTL layout — not just mirrored LTR.

10

One design system, every screen

A shared component library — cards, rating rows, bottom nav, empty states, loading states — so the same activity doesn't render as two different components depending which screen it's on.

If we only fix 5 things first

  1. Pull dev placeholder strings out of production — "Location Should Here," literal "string," raw i18n keys. Near-zero effort, maximum trust damage if left in.
  2. Add a visible, persistent booking CTA on the activity detail screen — this is the one screen whose job is to convert.
  3. Unify the bottom navigation across every screen — currently different items in a different order depending where you are.
  4. One shared card + rating component for activities, used everywhere instead of two competing versions.
  5. Fix placeholder-text contrast and add a calendar legend — cheap, concrete accessibility and comprehension wins.

Reimagining skillvera.sa

1

Distinctive typography, not template defaults

Montserrat at heavy weight is the single most-reused "AI-built SaaS site" font on the web right now — it's the tell. Pair a characterful display face for headlines (something like Fraunces or Recia for institutional warmth, or a refined grotesk like General Sans/Aeonik for a sharper tech feel) with a quieter, well-hinted body face (Inter or Satoshi). Keep Cairo for Arabic but choose it deliberately, not by default. Type alone will make the site feel designed rather than generated.

2

Story-driven hero

Replace the static gradient-blob hero and stock photo of a person facing away from camera with a short product-explainer loop, real photography, or scroll-triggered motion that shows, not tells, what SkillVera builds.

3

Interactive product explorer

Each product gets its own page with a live-feeling preview (app screenshots in a device frame, a working demo widget) instead of five cards linking to the same "Read more."

4

A living impact dashboard

Animated counters — facilities managed, activities hosted, learners reached — turning the Vision 2030 narrative into something visitors can see move.

5

Case studies & social proof

Client logos, sector testimonials, before/after stories per vertical (Gov, Education, Sports, Health, Corporate) — currently the site asserts credibility, doesn't demonstrate it.

6

A restrained, opinionated design system

Retire the one-pastel-gradient-per-card rainbow and the fully-rounded pill button used for every single action — pick two or three intentional accent treatments and a consistent corner-radius scale instead of Tailwind defaults left untouched.

7

Close the mobile performance gap

Desktop already scores a strong 94 on PageSpeed — the engineering foundation is solid. Mobile sits at 83 with LCP at 4.1s; PageSpeed's own top insight is ~1.4 MB of recoverable image savings. A targeted image-optimization and lazy-load pass, not a rebuild, closes this.

8

Smooth AR/EN switching

Persist language preference, animate the transition, and eliminate layout reflow between RTL and LTR instead of a hard reload — and fix the header direction bug flagged above.

9

Conversion-focused CTAs

A real "Book a discovery call" flow with a short qualifying form, not just phone/email/WhatsApp chips — capture and route leads instead of hoping they call.

10

Accessible by default

Color contrast, keyboard navigation, and screen-reader labelling as a baseline — not an afterthought — especially given the government/education client base.

11

Light content control

A minimal CMS or structured content layer so the SkillVera team can update team photos, copy, and case studies without opening a dev ticket every time.

On-page SEO

English page's title tag is in Arabic

<title> on /en reads "الموقع الرسمي Skillvera" — identical to the /ar title, zero English keywords. The highest-weight on-page ranking signal is currently non-functional for English search intent.

Technical SEO

No sitemap.xml or robots.txt

Both return 404. Google has no crawl map beyond incidental discovery. A same-day fix in Next.js (app/sitemap.ts, app/robots.ts), not a project.

Brand risk

Name collision drowns them in search

Branded searches for "Skillvera" surface skillvera.org (manpower services), skill-vera.com (a skills-verification platform), and similarly-named competitors — with SkillVera's own site not indexed at all. A government evaluator googling the name before a meeting may land on someone else first.

Structured data

Schema present but thin

Only Organization + WebSite JSON-LD, and "sameAs": [] is empty despite real LinkedIn/Facebook pages existing. No LocalBusiness or ContactPoint schema despite having a real Riyadh address relevant to local/B2G search.

Local presence

No Google Business Profile found

Unclaimed or nonexistent — a direct, low-effort win for local trust signals and brand-name search disambiguation.

Content

No case studies, blog, or Insights section

Nav is Home/About/Services/Products/Contact only. For a B2G/B2B RFP-driven sales motion, generic keyword SEO matters less than sector case studies sales can cite in proposals and on LinkedIn.

Social

Social is real but dormant, not fake

LinkedIn (29 followers, founded 2025), Facebook, and YouTube pages all exist — last LinkedIn post was 7+ months ago and was a job listing, not company content. The on-site social icons are disabled entirely. For a KSA B2G/B2B buyer, LinkedIn is the one channel worth reactivating (decision-makers check it before a meeting); X/Instagram activity isn't worth the investment for this buyer type.

Conversion

Contact path is fine, tracking it isn't

Phone/WhatsApp/email chips actually match how KSA B2G/B2B relationship-driven sales works — not a real gap on their own. The real miss is that none of those chips fire a trackable conversion event, so there's no way to measure inbound interest without asking the client directly. A simple qualifying form or GA4 click-tracking on the existing chips fixes this cheaply.

What's already fine: hreflang and canonical tags are correctly reciprocal per locale, OG tags are complete, meta descriptions are properly localized (unlike the title tag), robots meta is index, follow, and the direct-contact-chip approach itself suits this market. Not independently verifiable from outside: Search Console data, backlink profile/domain authority, internal GA4/analytics — request client access before finalizing SEO scope.
