Introduction

Plan on a Page

Scope

  • Part 1: complete Odoo 18 → 19 upgrade of the six companies, same database, history intact.
  • Part 2: Urban Eats / MYLK on Odoo 19 — structure, central kitchen, POS & Kitchen Display, delivery platforms, payments, ZATCA, WhatsApp, loyalty, Foodics exit.
  • Scope, prices and terms as in CX-TARA-2026-02 Rev. 1; this plan does not change them.

How it runs

  • Standard Odoo first: standard › configuration › Studio › supported module › custom, each custom item justified and approved.
  • Requirements and upgrade in parallel: workshops run in Weeks 1–2 while the upgrade is validated.
  • Dated and linked: every task has start, end, owner and dependency (column “Needs”).
  • Visible: Odoo Project portal, Thursday status report, fortnightly steering.

Environments (Odoo.sh)

  • Production: the six live companies; upgraded only after sign-off; Urban Eats deployed in cutover week.
  • Staging · upgrade: production copy upgraded to Odoo 19 for before / after checks.
  • Staging · build & UAT: Urban Eats built here; UAT environment rebuilt from a fresh production copy on 1 Dec with the go-live deployment package.
  • GitHub repository in Tara Holding’s name: custom modules, migration scripts, deployment notes.

Change control & defects

  • Change request: logged in the tracker; impact on scope, cost and dates given before work starts; starts only on written approval.
  • Custom item: written justification against the standard-first order; design approved by the Co-founder and Project Owner.
  • Code freeze from 24 Dec: Critical fixes only.
  • Severity: Critical = showstopper · High = key function impaired, workaround exists · Normal = minor. Each defect has an ID, owner and status in Helpdesk.
