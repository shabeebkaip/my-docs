SIP Trunk Requirements
Telephony — STC Infrastructure

SIP Trunk Requirements

AIKA connects to Vitality's existing STC SIP trunk. The following must be configured and confirmed before end of Week 1.

CONNECTIVITY DETAILS

  • SIP server hostname or IP address + port number
  • SIP domain / realm
  • SIP transport protocol preference (UDP / TCP / TLS — TLS preferred)
  • SIP trunk username & password / authentication credentials
  • Outbound proxy address (if applicable)
  • DTMF mode (RFC2833 strongly preferred)
  • Supported audio codecs (G.711 µ-law / a-law, G.729 — confirm supported)

NUMBERS & CAPACITY

  • DID number(s) to be assigned to AIKA (minimum 1 inbound DID)
  • Maximum concurrent call capacity required
  • Call routing rules (business hours vs. after-hours behaviour)
  • Existing IVR to be retired or migrated?

NETWORK & SECURITY

  • Firewall IP whitelist — CodeOx cloud IPs must be whitelisted
  • SIP ALG on NAT device (must be disabled for reliable calls)
  • QoS / DSCP markings for RTP traffic
  • STC technical contact name + direct number
❓

Open Question for Vitality

Has STC already been engaged for this project? STC DID provisioning typically takes 1–2 weeks. If not yet initiated, this process must begin today to avoid delaying the go-live date.

Nixpend HMS Integration
System of Record — HMS / ERP

Nixpend HMS Integration Requirements

Nixpend HMS is the core system of record. Every booking from AIWA and AIKA writes back here. We assume REST API — please confirm below.

API ACCESS & ENVIRONMENT

  • Full API documentation (Swagger / OpenAPI spec preferred)
  • Sandbox / staging environment URL
  • Sandbox API credentials (username/password or API key)
  • Authentication method (OAuth 2.0 / API Key / JWT / Basic Auth?)
  • API base URL + versioning format
  • Rate limits and throttling policy
  • Nixpend technical contact for API support queries

REQUIRED API ENDPOINTS

  • Patient lookup / search by phone number or ID
  • Create new patient record
  • Booking creation (service, date, time, patient, therapist)
  • Booking update / cancellation
  • Therapist availability query (by date + district)
  • Service catalog / service type list
  • District / zone mapping data
  • Booking status read-back
  • Webhook / callback support? (for async status push)
⚠️

Assumption: Standard REST API. If Nixpend uses SOAP, direct DB, or file-based integration, timeline and cost will need revision.

❓

Open Question: Is Nixpend HMS currently live and operational? Is the sandbox stable and representative of production data?
